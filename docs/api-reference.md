# API reference

How to drive the engine from TypeScript: `createGame`, the `Game` object, the wasm `World`'s state and scratch buffers, raycasts and the `window.__pebble3d` probe. The member lists further down are generated by `pnpm docs:gen`.

Task-sized examples: [cookbook/](cookbook/README.md). Where each feature is used in the games: [examples.md](examples.md).

## createGame

`createGame(opts)` parses and expands the scene, loads the wasm build named by `scene.sim.build`, spawns every entity, builds the renderer and the entity visuals, and returns a `Game`. It does not start: call `game.start()`. Source: `packages/sdk/src/game.ts`.

| Option | Type | Default | Meaning |
| --- | --- | --- | --- |
| `canvas` | `HTMLCanvasElement` | required | Render target. Sized from `clientWidth`/`clientHeight` (DPR capped at 2) and re-sized by a `ResizeObserver`. |
| `scene` | `SceneInput` | required | Scene JSON. Validated with `parseScene`; a bad scene throws `SceneError` with the field path. |
| `wasmUrls` | `{ deterministic: string; fast: string }` | required | URLs of both `_bg.wasm` builds; only the one `scene.sim.build` names is loaded. |
| `mode` | `"realtime" \| "fixed"` | `"realtime"` | `realtime`: ticks follow wall time, at most 5 per frame (the excess is dropped). `fixed`: exactly one tick per frame, render alpha 1 (screenshots, reproducible captures). |
| `stopAtTick` | `number` | none | Fixed mode only: the sim stops advancing at this tick and `__pebble3d.done` turns true once that frame has rendered. |
| `backend` | `"webgpu" \| "webgl"` | `"webgpu"` | A WebGPU request that falls back throws `BackendUnavailable: webgpu`; retry on a fresh canvas with `"webgl"` (`apps/playground/src/main.ts`, lines 200-212). |
| `splatOnly` | `boolean` | `false` | Debug: draw only the splat, no meshes or post. |

What happens each frame, in order:

1. `FixedStepLoop.advance` decides the tick count; `world.step(n)` runs them.
2. Bodies created by spawners are drained (`drainSpawned`) and given visuals (`renderer.addSpawned`).
3. `views.refresh()`, then `renderer.sync(prev, curr, alpha)` interpolates every body.
4. The player callback reads `characterState`, updates the character view and third-person camera, and sends `setCharacterInput` for the **next** tick.
5. Your `onFrame` callbacks run, in registration order.
6. `renderer.render(dt)`; `__pebble3d.frame`/`tick`/`ready`/`done` update.

There is no per-tick hook. To run game rules once per tick, either count `world.tick()` inside `onFrame` (getting-started's `while (sim.tick < world.tick())`) or own the loop (see [cookbook/deterministic-game-loop.md](cookbook/deterministic-game-loop.md)).

## The Game object

| Member | Meaning |
| --- | --- |
| `start()` / `stop()` | Start or cancel the `requestAnimationFrame` loop. `start()` twice is a no-op. |
| `sim` | `SimHandle`: `world` (the wasm `World`), `memory` (its `WebAssembly.Memory`), `build`, `seed`, `spawnScene(entries)`. |
| `views` | `StateViews`: `prev`, `curr` (Float32Array, 8 floats per slot), `scratch` (Float32Array of `SCRATCH_LEN`), `capacity`, `refresh()`. |
| `ids` | `Map<sceneId, simId>`. Includes the generated `__ground` and `__bounds.<side>` statics. Spawner-created bodies are not in it. |
| `player` | `PlayerRig \| null`, the scene's first entity with a `character`: `simId`, `view` (a `CharacterView`), `camera` (`ThirdPersonController` when `camera.controller` is `"thirdPerson"`, else null), `input` (`{ keys: { f, b, l, r }, jump, sprint }`). Keyboard listeners (WASD/arrows, Space, Shift) write `input`; scripts and bots may write it directly. |
| `renderer` | `EngineRenderer`: `three` (`renderer`, `scene`, `camera`), `controller`, `instances`, `dof`, `splatColor`, `style`, `stylize(root)`, `loadGltf(url)`, `setCameraPreset(name)`, `reportError(msg)`. |
| `onFrame(cb)` | `cb(dt)` every frame after `renderer.sync`, before `render`. `dt` is wall seconds in realtime and `ticks / 60` in fixed mode (`1/60`, or 0 once stopped). |
| `setCamera(name)` | A camera preset from `camera.presets`, or `"controller"` to hand back to the scene's controller. A preset suspends the third-person camera; the player still moves relative to its yaw. |
| `stats()` | `GameStats` (fps, frameMs, drawCalls, triangles, splats, physicsMs, activeBodies, sleepingBodies, build, tick, errors). Returns the same mutated object every call. |

Read state from `views` only after `views.refresh()`: wasm memory can grow on any spawn, which detaches old typed-array views. `createGame` refreshes once per frame before `onFrame`; refresh again after you spawn or step yourself.

## State buffers

Each body with a slot occupies 8 `f32` in both `views.prev` and `views.curr` (`STATE_STRIDE = 8`, the renderer's mirror in `packages/renderer/src/dynamics/instances.ts` of the Rust `STRIDE` in `crates/engine-core/src/slots.rs`). Get the slot with `world.slotOf(simId)` (-1 if none); slots are reused after `despawn`.

| Offset | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Value | `px` | `py` | `pz` | `qx` | `qy` | `qz` | `qw` | `flags` |

| Flag bit | Value | Meaning |
| --- | --- | --- |
| `ACTIVE` | 1 | The slot holds a live body (a freed slot reads 0). |
| `SLEEPING` | 2 | Rapier put the body to sleep. |
| `NO_INTERP` | 4 | Snap, don't interpolate: set on spawn and by `teleport`, cleared after the next tick. |

The flags are stored as a float; read them with `views.curr[slot * 8 + 7] & 4` style integer tests (JS converts). The constants are exported from `@pebble3d/renderer` (`ACTIVE`, `SLEEPING`, `NO_INTERP`, `STATE_STRIDE`). `readSlot(prev, curr, slot, alpha, outPos, outQuat)` writes the interpolated pose and honours `NO_INTERP`. `prev` is the pose before the last tick, so `prev + (curr - prev) * alpha` is the render pose.

## Scratch buffer

Query methods write results into a fixed `SCRATCH_LEN` (24) float region at `world.scratchPtr()` and return `true`; `views.scratch` is a view over it. They return `false` and leave the scratch untouched when the id is unknown (or not a character, for `characterState`). Read the values right away: the next query overwrites them.

| Method | Writes | Indices |
| --- | --- | --- |
| `raycast(...)` | `toi, nx, ny, nz, hitId` | `[0..5)` |
| `characterState(id)` | `grounded (0/1), vx, vz, vy` (note the order: vz before vy) | `[8..12)` |
| `linearVelocity(id)` | `vx, vy, vz` (m/s) | `[12..15)` |
| `angularVelocity(id)` | `wx, wy, wz` (rad/s) | `[16..19)` |

`world.scratchLen()` returns 24 and the sdk's `SCRATCH_LEN` mirrors it (a test checks the match). Indices 5-7, 15 and 19-23 are unused.

## Raycasts

```ts
const hit = world.raycast(ox, oy, oz, dx, dy, dz, maxToi, filter, excludeId);
if (hit) {
	const sc = game.views.scratch;
	const dist = sc[0], hitId = sc[4]; // normal: sc[1], sc[2], sc[3]
}
```

| `filter` | Hits | `excludeId` |
| --- | --- | --- |
| `0` | every collider | ignored (pass 0) |
| `1` | static bodies only (ground, bounds, static entities) | ignored |
| `2` | everything except the body of `excludeId` | the entity to skip (the caster itself) |

The direction is normalised for you, so `toi` is metres. `hitId` is the entity id (compare with `game.ids`). Raycasts see the broad phase as of the last `step`: a body spawned since then is invisible until the next tick. A zero direction or `maxToi <= 0` returns false. The third-person camera uses filter 1 so moving props never pull the camera in.

## Body control

All take the entity id and return `false` for unknown ids or the wrong body type.

| Method | Works on | Effect |
| --- | --- | --- |
| `applyImpulse(id, ix, iy, iz)` | dynamic | Adds `impulse / mass` to the velocity (N·s); wakes the body. |
| `applyTorqueImpulse(id, tx, ty, tz)` | dynamic | Angular impulse; wakes the body. |
| `setVelocity(id, vx, vy, vz, wx, wy, wz)` | dynamic | Sets linear and angular velocity; wakes the body. |
| `setKinematicPose(id, px, py, pz, qx, qy, qz, qw)` | kinematic | Target pose, reached on the next step. |
| `teleport(id, x, y, z)` | any with a body | Moves instantly, zeroes a dynamic body's velocity, sets `NO_INTERP`. Returns nothing. |
| `setCharacterInput(id, wx, wz, jump, sprint)` | character | World-space XZ direction (clamped to length 1). `createGame` overwrites it every frame for `game.player`. |
| `spawn(json)` / `despawn(id)` | | `spawn` takes an `EntityDescJson` string (camelCase: `position`, `rotation`, `body: { type, mass, friction, restitution, linearDamping, angularDamping, ccd, collider }`, `character`, `spawner`) and returns the id; it throws on bad JSON. Bodies spawned this way get no visual: add one yourself. |

Default mass is collider volume at density 1 (a 1 m box is 1 kg, a 0.5 m radius sphere about 0.52 kg).

## The `window.__pebble3d` probe

`createGame` installs it; `pnpm shot` and benches read it ([verification.md](verification.md)).

| Field | Meaning |
| --- | --- |
| `ready` | True once the first frame rendered. |
| `done` | Fixed mode: true once the frame at `stopAtTick` rendered. |
| `frame`, `tick` | Frames rendered, current sim tick. |
| `stats()` | `GameStats`. |
| `adapterInfo` | `{ backend, vendor, architecture, device, description }`; `pnpm shot` refuses SwiftShader. |
| `stateHash()` | `world.stateHash()`: 16 hex chars, FNV-1a 64 over the sim state. |
| `setCamera(name)` | As `game.setCamera`. |
| `player()` | `{ position, grounded, velocity, anim, modelMinY, camera, arm }` or null. Allocates. |
| `position(sceneId)` | `[x, y, z]` of a scene entity's body, or null. Allocates. |
| `error` | Set by your `main().catch` so automation reports the failure instead of timing out. |

Add game probes with `Object.assign(window.__pebble3d ?? {}, { game: { score: () => sim.score } })`. `pnpm shot` calls every function in `game` and writes the results to the sidecar. An app that uses the engine with its own world (Chain Reaction) can override `stateHash` the same way so captures report that world. An app that boots without `createGame` must install the whole hook itself: `ready`, `done`, `frame`, `tick`, `stats`, `adapterInfo`, `stateHash`, `setCamera` (`apps/rockfall/src/main.ts`, lines 274-322).

## Booting without createGame

For a sim that owns its world (bodies created in code, a different tick rate cap, a worker), compose the parts as `apps/rockfall/src/main.ts` does (lines 180-199 and 324-411):

```ts
const scene = parseScene(sceneJson);
const x = expandScene(scene); // x.settings feeds the renderer; x.sim are the spawn descs
const [handle, renderer] = await Promise.all([
	loadSim(scene.sim.build, wasmUrl, { seed: scene.sim.seed, gravity: scene.sim.gravity }),
	createRenderer(canvas, x.settings, { backend: "webgpu" }),
]);
const loop = new FixedStepLoop({ mode, maxTicksPerFrame: 2 });
// per frame: adv = loop.advance(dt, tick); step adv.ticks times;
// views.refresh(); renderer.sync(views.prev, views.curr, adv.alpha); renderer.render(dt);
```

In Node, pass the wasm bytes instead of a URL: `loadSim("deterministic", readFileSync(".../engine_core_det_bg.wasm"))` (`apps/chain-reaction/src/puzzle/node-engine.ts`). More worlds in the same module: `new (handle.world.constructor)(seed, gravity)`; each needs its own `StateViews`-style views and must be `free()`d (`apps/ghostline/src/game/physics.ts`).

## Headless: SimHandle, SimEntry, StateViews

The `@pebble3d/sdk/sim` types you need to run a scene in Node (or own the world in the browser). Full worked example: [cookbook/json-levels-and-headless-verify.md](cookbook/json-levels-and-headless-verify.md#spawn-a-scene-and-read-state-in-node).

| Name | Shape | Notes |
| --- | --- | --- |
| `loadSim(build, wasm, opts?)` | `Promise<SimHandle>` | `wasm` is a URL (browser, async fetch) or the `_bg.wasm` bytes (Node, sync init). `opts`: `{ seed?: number; gravity?: number }`, defaults 1 and -9.81; pass `scene.sim.seed` / `scene.sim.gravity` to match `createGame`. |
| `SimHandle` | `{ world: World; memory: WebAssembly.Memory; build: SimBuild; seed: number; spawnScene(entries: SimEntry[]): Map<string, number> }` | `spawnScene` spawns in order and returns sceneId -> sim id (the same map as `game.ids`). |
| `SimEntry` (`@pebble3d/sdk/types`) | `{ sceneId: string; desc: EntityDescJson }` | What `expandScene(scene).sim` holds: `__ground`, then `__bounds.<side>`, then each entity. `desc` is the JSON `World.spawn` parses (`spawnScene` calls `world.spawn(JSON.stringify(e.desc))`). Entries listed in `pendingHulls` need glTF hull points first; Node skips them. |
| `new StateViews(handle)` | `prev`, `curr`, `scratch` (`Float32Array`), `capacity`, `refresh(): boolean` | Needs only `handle.world` and `handle.memory`, so a second world gets views with `new StateViews({ ...handle, world: w2 })`. Call `refresh()` after spawning or stepping before reading. |

Reading a body: `slot = world.slotOf(id)`, position `views.curr[slot * 8 + 0..2]` ([State buffers](#state-buffers)); velocity `if (world.linearVelocity(id))` then `views.scratch[12..14]` ([Scratch buffer](#scratch-buffer)). In tests, `world.transformOf(id)` returns `[px, py, pz, qx, qy, qz, qw]` (allocates).

Tick order: `createGame` steps physics and then calls `onFrame`, so a headless run that must reproduce a `createGame` app's `stateHash` does `world.step(1); views.refresh();` and then the rules, every tick ([getting-started.md](getting-started.md#tick-order)).
